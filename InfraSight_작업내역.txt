 InfraSight - 통합 인프라 관제 시스템 작업 내역
 (Brainz Zenius EMS 참고하여 제작)
====================================================================

■ 프로젝트 개요
--------------------------------------------------------------------
브레인즈 Zenius EMS v9.0 요약본을 참고해서, 서버·DB·네트워크·전산실
설비를 한 화면에서 모니터링하는 실제 동작하는 로컬 관제 시스템을
만들었습니다. 처음엔 가짜 데이터로 만든 데모였지만, 사용자 요청에
따라 이 PC와 실제 네트워크 장비를 실측하는 진짜 서비스로 발전시켰
습니다.

위치: D:\Agent\Claude\infrasight-dashboard\
접속: http://localhost:5057  (같은 네트워크에서는 http://<이 PC IP>:5057)
실행: start.bat 더블클릭


■ 만든 순서대로 정리한 작업 내역
--------------------------------------------------------------------

[1] 대시보드 프로토타입 제작
    - Zenius EMS의 화면 구조(전체 현황 / 토폴로지 맵 / 서버·DB·네트워크
      ·설비 관리 / 이벤트 관리)를 참고해 웹 대시보드로 재구성
    - 처음엔 가짜(랜덤) 데이터로 동작하는 데모로 시작
    - 다크 테마의 관제센터(NOC) 스타일 UI, Chart.js 기반 실시간 그래프
    - 파일: index.html

[2] 장비 등록 기능 추가
    - "장비 등록" 메뉴 신설 - 서버/DB/네트워크/설비를 직접 추가 가능
    - 등록 즉시 토폴로지 맵과 각 목록에 반영

[3] 데모 → 실제 서비스로 전환 (가장 큰 변화)
    - Python Flask 백엔드 서버 신설 (server.py)
    - 이 PC(로컬)는 psutil로 실제 CPU/메모리/디스크/네트워크/프로세스
      측정 (더 이상 가짜 숫자 아님)
    - SQLite DB에 등록 장비 영구 저장 (브라우저 새로고침해도 유지)
    - 장비 등록 방식 3가지 도입:
        1) Agent   - 다른 PC에 프로그램을 설치해 실측 (CPU/메모리 등 전체)
        2) Ping    - 설치 없이 IP 도달성 + 응답시간만 확인
        3) SNMP    - 스위치/라우터/UPS 등 SNMP 지원 장비의 상세 정보 실측
    - agent.py 제작: 다른 PC에서 실행하면 실측 데이터를 이 서버로 전송

[4] SNMP 기능 확장
    - 네트워크 장비 등록 시 SNMP(Community/버전/포트)로 실측 가능하도록 개발
    - 장치 정보(sysDescr), 응답시간, 인터페이스 상태 실측
    - 실제 보유 중인 Cisco 스위치로 검증 완료

[5] 버그 수정 - 토폴로지 맵 안 보이는 문제
    - 원인: 데이터 도착 전에 지도를 한 번만 그리고, 이후엔 새로 등록된
      장비 노드를 다시 그리지 않는 구조적 문제였음
    - 장비 구성이 바뀔 때마다 지도를 다시 그리도록 수정
    - 함께 발견한 문제: SNMP/Ping 통신 중 전체 데이터를 잠가버려서
      화면 갱신이 지연되는 문제도 같이 개선

[6] 네트워크 장비 CPU/메모리/인터페이스 모니터링 추가
    - 토폴로지 맵에 마우스를 올리면 CPU/메모리/인터페이스 상태를
      바로 확인 가능
    - 클릭하면 상세 정보(장치 설명, CPU/메모리 추이 그래프, 인터페이스
      목록, 트래픽 추이) 표시
    - 인터페이스 목록에서 개별 인터페이스 클릭 시 실시간 트래픽을
      보여주는 별도 팝업창 도입

[7] 인터페이스 목록 버그 수정
    - "인터페이스가 계속 최상위로 올라가는" 문제 수정
      (실시간 갱신마다 목록 스크롤 위치가 초기화되던 문제)
    - 트래픽 수치가 소수점 반올림 때문에 항상 "0.0"으로 보이던 문제 개선
      (예: 0.023 Mbps처럼 정밀하게 표시)

[8] 네트워크 장비 상태 모니터링 강화
    - "네트워크 관리" 화면 표에 CPU · 메모리 · 트래픽 · Uptime 컬럼 추가
      (클릭 안 해도 목록에서 바로 확인 가능)
    - 발견한 버그: SNMP 조회를 하나로 통합하는 과정에서 Uptime(가동시간)
      수집이 빠져있던 것을 발견하고 복구

[9] 에이전트 설치 방식 개선 (PC 등록 편의성 개선)
    - 기존: python 명령어를 직접 입력해야 하는 불편함
    - 1차 개선: Python 설치 없이 실행되는 단일 실행 파일
      (InfraSightAgent.exe, PyInstaller로 제작) 제공 + Windows 로그인 시
      자동 시작 등록 기능
    - 2차 개선(최종): 서버 주소·토큰을 직접 입력할 필요 없이,
      "설치 파일 다운로드 → 더블클릭"만으로 끝나는 원클릭 설치
      스크립트(InfraSight-Install.bat) 자동 생성 기능 추가
        - 더블클릭 시: 프로그램 다운로드 → 설정 저장 → 자동 시작 등록
          → 모니터링 시작까지 전부 자동
    - 수동 설치를 원하는 사용자를 위해 기존 방식은 "고급" 메뉴에 보존

■ 장비 등록 방법 요약
--------------------------------------------------------------------
1) 다른 PC (서버로 등록, CPU/메모리까지 보고 싶을 때)
   → "장비 등록" > 서버(SMS) > Agent 설치 > 등록
   → 나오는 "설치 파일 다운로드" 버튼 클릭 → 대상 PC에서 더블클릭
   → 끝. 이후 자동 시작됨.

2) 공유기/스위치/NAS/DB서버 등 (켜져있는지만 확인하고 싶을 때)
   → 카테고리 선택 > Ping > IP만 입력 > 등록
   → 설치 아무것도 필요 없음

3) SNMP 지원 스위치/라우터/UPS (장치 정보, 트래픽, CPU/메모리까지)
   → 카테고리 선택 > SNMP > IP + Community 문자열 입력 > 등록
   → 장비의 SNMP 설정을 미리 켜두고, Community 값을 확인해둘 것


■ 알아두면 좋은 점 / 한계
--------------------------------------------------------------------
- 개발용 Flask 서버라서 집/사무실 등 소규모 네트워크 용도에 적합합니다.
  외부 인터넷에 노출하거나 다수 동시 접속이 필요하면 별도 조치가 필요합니다.
- SNMP로 CPU/메모리/인터페이스까지 보려면 그 장비가 해당 정보를
  지원해야 합니다. 지원하지 않으면 억지로 숫자를 만들지 않고 "-"로
  정직하게 표시됩니다.
- 에이전트 자동 시작은 콘솔 창이 최소화된 채로 실행됩니다
  (완전히 숨겨진 백그라운드 실행은 아직 아님).
- 이 PC(로컬)는 항상 자동으로 실측 등록되어 있어 별도 등록이 필요 없습니다.
