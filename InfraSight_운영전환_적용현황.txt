■ DB에 새로 생긴 테이블
--------------------------------------------------------------------
  users          로그인 계정 (현재 admin 1명)
  audit_log      "누가 언제 무엇을 했는지" 기록 (로그인/등록/삭제/확인 등)
  credentials    SNMP community, SNMPv3 비밀번호 등 민감정보 전용 테이블
  settings       SMTP 등 전역 설정값
  metrics_raw    최근 3일치 실측값 원본 (CPU/메모리/트래픽/응답시간)
  metrics_5m     5분 단위로 압축한 값 (90일 보관)
  metrics_1h     1시간 단위로 압축한 값 (1년 보관)
  device_links   LLDP로 찾아낸 장비 간 연결 관계
※ 기존 devices/incidents 테이블은 컬럼만 추가됐고, 있던 데이터는 전부 그대로
  보존되어 있습니다 (장비 5대, 이벤트 이력 146건 - 실측 확인).

 Phase 1 - Collector 분리 + 스케줄러 + Timeout/Retry + 5단계 상태
====================================================================
[완료]
 - 장비 감시 로직을 server.py에서 collector/ 폴더로 전부 이관
 - 예전: 모든 장비를 한 줄로 세워 순서대로 감시 (한 장비가 느리면 전체가 밀림)
 - 현재: 장비마다 독립된 스케줄 작업으로 병렬 감시 (APScheduler, 워커 10개)
 - 장비별로 폴링 주기 · timeout · 재시도 횟수를 다르게 설정할 수 있는
   구조 마련 (지금은 전 장비 기본값 2초로 동일 - 필요할 때 개별 조정 가능)
 - "1번 응답 없으면 바로 위험" 이던 것을 "연속 실패 횟수" 기반으로 개선
   → 실제로 스위치가 일시적으로 반응 늦었을 때 바로 "위험"이 아니라
     "주의"로만 뜨고 금방 복구되는 것을 실측으로 확인함 (오탐 감소)
 - 개발용 Flask 서버 → waitress(운영급 서버)로 교체
 - InfraSight 자체 상태 확인 API 신설 (Web/DB/Collector 각각 살아있는지)

[알아두면 좋은 점]
 - 서버 재시작해도 에이전트가 최근에 보고했던 시각을 기억해서, 재시작
   직후에 바로 "오프라인"으로 오판하지 않음 (예전엔 재시작하면 무조건
   전부 오프라인으로 보였음)

 Phase 2 - 이벤트 재설계 + 복구 처리 + 유지보수 모드
====================================================================
[완료]
 - 같은 장비에서 같은 문제가 반복되면 이벤트를 새로 쌓지 않고 "발생
   횟수"만 올라가도록 개선 (예전엔 2초마다 계속 새 이벤트가 쌓였음)
 - [실제로 발견해서 고친 버그] 장비가 복구돼도 예전 "위험" 이벤트가
   영원히 "미해결" 상태로 남아있던 문제 발견 → 복구되면 자동으로
   해당 이벤트를 "해결됨"으로 닫도록 수정. (화면 상단 "미해결 N건"
   숫자가 이제 실제로 줄어듦)
 - 이벤트 확인(ACK) 처리 시 "누가" 확인했는지 기록되도록 개선
 - 유지보수 모드 신설: 장비를 점검 중으로 표시해두면 감시는 계속하되
   이벤트/알림만 안 울리게 처리 (점검 중에 진짜로 복구됐는지도 계속
   확인 가능)

 Phase 3 - 로그인 + 감사 로그 + 민감정보 분리
====================================================================
[완료]
 - 브라우저로 InfraSight에 접속하면 이제 로그인 화면부터 나옴
   (외부인이 그냥 URL만 알아도 볼 수 없도록 차단)

 - "누가 언제 무엇을 했는지" 감사 로그 자동 기록 (로그인/로그아웃/
   장비 등록·삭제/이벤트 확인/유지보수 설정/알림 설정 변경 등)
 - SNMP community(비밀번호 격) 문자열을 장비 정보와 분리된 별도
   테이블로 이전 - 화면에는 어차피 원래도 안 보였지만, 이제 DB
   저장 방식 자체도 더 안전해짐

 Phase 5 - 지표 이력 보존 + DB 자동 백업
====================================================================
[완료]
 - [실제로 발견해서 고친 문제] 예전엔 CPU/메모리/트래픽 그래프가
   메모리에만 있어서 서버 재시작하면 그래프 이력이 통째로 사라짐
   → 이제 실제 DB에 기록되어 재시작해도 이력이 남음
 - 최근 3일은 원본 그대로, 그 이후는 5분/1시간 단위로 압축 보관
   (90일 / 1년) - 오래된 데이터도 대략적인 추이는 계속 볼 수 있음
 - 매일 새벽 3시에 DB를 자동 백업 (최근 14개만 보관, 그 이전 것은
   자동 삭제) - 쓰는 도중에도 안전하게 백업되는 방식 사용
 - 필요하면 언제든 수동으로 백업 1회 실행 가능

====================================================================

 Phase 7 - SNMP 고도화 (벤더 프로파일 / SNMPv3 / LLDP)
====================================================================
[완료]
 - 벤더별로 다른 OID(장비 정보 위치)를 쓰는 구조를 정리 - 지금은
   generic(일반)/cisco/ups 3종류, 나중에 다른 회사 장비 추가도 쉬움
 - SNMPv3(암호화된 SNMP) 지원 추가 - 로그인 정보(계정/암호화 방식/
   비밀번호)는 전부 안전한 테이블에 저장
 - [실제 테스트로 발견한 문제] SNMPv3 암호화에 필요한 라이브러리가
   이 PC에 아예 없었음 → 설치함. 그리고 MD5+DES 조합은 이 환경에서
   실제로는 안 되고, SHA+SHA256/AES 조합만 정상 동작하는 것까지
   실측 확인함 (나중에 SNMPv3 장비 등록할 때는 SHA/AES를 사용해야 함)
 - 스위치 간 실제 연결 관계(LLDP)를 자동으로 찾아서 저장하는 기능
   추가 - 다만 화면 지도는 예전 방식 그대로 유지 (지시서에 그렇게
   하라고 되어있었음), 데이터만 미리 준비해둔 상태

 Phase 4 - 이메일 알림 (진행 중 - 사용자 확인 대기)
====================================================================
[코드는 완료, 실제 발송만 막혀있음]
 - 위험 등급 이벤트가 새로 발생하거나 심각도가 올라갈 때만 메일
   발송 (같은 문제 반복돼도 매번 보내지 않음, 스팸 방지)
 - 메일 서버 설정 화면/API, 테스트 발송 기능까지 전부 완성
 - 메일플러그(help@next-ict.co.kr) 계정으로 실제 발송을 시도했는데,
   메일 서버가 로그인 자체를 거부함:
     서버 응답: "535 5.7.0 553 sorry, that password allowed relay"
 - 네트워크나 코드 문제가 아니라 메일플러그 계정에 외부 프로그램
   (SMTP) 발송 권한이 아직 열려있지 않은 것으로 보임
 - → 메일플러그 관리자 설정에서 이 계정의 SMTP 릴레이 허용을 켜신
   뒤 다시 확인 요청 주시면 됩니다
