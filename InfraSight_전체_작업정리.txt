■ 프로젝트 개요
--------------------------------------------------------------------
브레인즈 Zenius EMS v9.0 자료를 참고해서 만든 서버/DB/네트워크/전산실
설비 통합 관제 시스템입니다. 처음엔 가짜 데이터로 만든 데모였는데,
지금은 실제 이 PC와 실제 네트워크 장비(Cisco 스위치, 다른 PC들)를
실측하는 진짜 서비스로 완성됐고, 그 다음 "운영 수준으로 강화해달라"는
요청에 따라 41개 항목짜리 개발지시서를 바탕으로 7단계(Phase)에 걸쳐
프로덕션급으로 다시 다졌습니다.

지금까지 등록된 실제 장비 6대, 누적 이벤트 178건 — 작업 과정에서
데이터를 잃어버린 적 없이 전부 보존되어 있습니다.


====================================================================
 1부. 데모 → 실제 서비스 전환 (초기 작업)
====================================================================
 1. 대시보드 프로토타입 - Zenius EMS 화면 구조를 참고한 NOC 스타일
    다크 테마 웹 대시보드 (처음엔 가짜 데이터)
 2. 장비 등록 기능 - 서버/DB/네트워크/설비를 직접 추가하는 화면
 3. 실제 서비스 전환 - Python Flask 백엔드 + SQLite DB 신설, 이 PC는
    psutil로 실측, 장비 등록 방식 3가지 도입 (Agent/Ping/SNMP)
 4. SNMP 기능 확장 - 실제 Cisco 스위치로 검증
 5. 버그 수정 - 토폴로지 맵 안 보이던 문제, Lock 경합으로 화면 갱신
    지연되던 문제
 6. 네트워크 장비 CPU/메모리/인터페이스 모니터링 추가, 인터페이스
    클릭 시 트래픽 팝업
 7. 인터페이스 목록 스크롤 튐 버그, 트래픽 수치 반올림 버그 수정
 8. 네트워크 장비 목록에 CPU/메모리/트래픽/Uptime 상시 표시
 9. 에이전트 설치 방식 개선 - 명령어 직접 입력 → 원클릭 설치
    스크립트(InfraSight-Install.bat)로 개선


====================================================================
 2부. 운영 전환 (Phase 1~7) - 프로덕션 강화
====================================================================
사용자가 작성한 41개 항목 개발지시서를 실제 코드 분석 결과에 맞춰
검토·구체화한 뒤(InfraSight_운영전환_개발지시서_v2.txt), 순서대로
7단계에 걸쳐 실제로 구현하고 실제 장비로 검증했습니다.

[Phase 1] Collector 분리 + 스케줄러 + 5단계 상태
 - 감시 로직을 server.py에서 collector/ 폴더로 분리 (장비마다 독립된
   스케줄 작업으로 병렬 감시, 한 장비가 느려도 다른 장비에 영향 없음)
 - "1번 실패=바로 위험" → "연속 실패 횟수 기반"으로 개선 (오탐 감소,
   실측으로 확인)
 - 개발용 서버 → waitress(운영급 서버) 교체
 - InfraSight 자체 상태 점검 API 신설

[Phase 2] 이벤트 재설계 + 복구 처리 + 유지보수 모드
 - 같은 문제 반복 시 이벤트 중복 생성 대신 "발생 횟수"만 증가
 - [실제 발견 버그] 장비 복구돼도 예전 이벤트가 영원히 "미해결"로
   남던 문제 발견 → 자동 해결 처리로 수정
 - 유지보수 모드 신설 (점검 중엔 감시는 계속, 알림만 억제)

[Phase 3] 로그인 + 감사 로그 + 민감정보 분리
 - 로그인 화면 도입 (admin 계정, 외부인 접근 차단)
 - 감사 로그 자동 기록 (누가 언제 무엇을 했는지)
 - SNMP 비밀정보를 별도 테이블로 분리 저장

[Phase 5] 지표 이력 보존 + DB 자동 백업
 - [실제 발견 문제] 재시작하면 그래프 이력이 사라지던 문제 →
   DB에 기록해서 재시작해도 이력 유지 (3일 원본 + 90일/1년 압축 보관)
 - 매일 새벽 3시 DB 자동 백업 (최근 14개 보관)

[Phase 6] 대시보드 개선
 - 서버/DB/네트워크/설비 4개 화면에 검색+상태 필터 통일 적용
 - 유지보수 모드 켜고 끄는 버튼을 장비 상세 화면에 연결
 - (최근 추가) 전체 화면 테마를 어두운 무채색에서 화려한 그라데이션
   + 글래스모피즘 + 네온 글로우 스타일로 전면 개편

[Phase 7] SNMP 고도화
 - 벤더별 OID를 프로파일 구조로 정리 (generic/cisco/ups)
 - SNMPv3(암호화) 지원 추가
 - [실제 테스트로 발견한 문제] 이 환경에 SNMPv3 암호화 라이브러리가
   없었음(설치함), MD5+DES 조합은 안 되고 SHA+AES 조합만 정상 동작
   하는 것까지 실측 확인
 - LLDP로 장비 간 실제 연결 관계 자동 탐색 (지도 표시는 예전 방식
   유지, 데이터만 미리 준비)

[Phase 4] 이메일 알림 - 코드는 완성, 실제 발송은 대기 중
 - 위험 이벤트가 새로 발생하거나 심각도가 올라갈 때만 메일 발송
   (반복 발생해도 스팸처럼 매번 보내지 않음)
 - 메일플러그(help@next-ict.co.kr) 계정으로 실제 발송 시도 →
   서버가 인증을 거부함: "535 5.7.0 553 sorry, that password
   allowed relay" → 메일플러그 관리자 설정에서 이 계정의 SMTP
   릴레이(외부 프로그램 발송) 허용이 필요한 것으로 확인됨
 - 설정 화면/API, 테스트 발송 기능까지 전부 완성되어 대기 중

====================================================================

   (지금은 API로만 등록 가능)

   있지만 지도 자체는 예전 방식 그대로
